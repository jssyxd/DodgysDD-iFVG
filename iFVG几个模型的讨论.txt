交易教育者 DodgysDD 推广的 Inversion FVG / iFVG，即反转公允价值缺口策略）是一种基于 ICT（Inner Circle Trader）概念的机械化价格行为交易模型。

核心逻辑：反应而非预测

• 传统 FVG（公允价值缺口）. 由三根 K 线组成，中间 K 线大幅波动导致第一根与第三根 K 线的影线没有重叠，形成价格失衡区。传统做法是等价格回踩该缺口时顺势入场。
• iFVG（反转公允价值缺口）. DodgysDD 的核心理念是“等待失效”。当价格回踩某个看涨 FVG 却未能获得支撑，反而用实体 K 线强势跌破该缺口时，原本的看涨支撑区就反转（Inverse）成了看跌阻力区。

标准交易步骤

1. 识别流动性扫荡（Liquidity Sweep）. 观察价格是否先猎杀了前期的高点或低点（扫止损），这是反转的前提信号。
2. 寻找初始 FVG. 在扫荡发生前后的波动中，标记出最近的一个反向 FVG 区域。
3. 等待强势突破（反转确认）. 价格反向移动，并用一根收盘价彻底穿过该 FVG 区域的 K 线将其“破坏”。
4. 回踩入场与风控. 在缺口被破坏后（或价格小幅回踩该已反转的 FVG 边缘时）顺着新方向入场，止损通常设在近期的波段高低点外侧，目标看向下一个流动性池（如前高/前低）。

适用场景与特点

• 常用周期与品种. 该模型常用于纳斯达克 100 指数期货（NQ）等高波动品种的短线（如 1 分钟至 15 分钟）交易，尤其是在美股开盘等高成交量时段。
• 工具辅助. 在 TradingView 上有专门针对该策略编写的指标（如 iFVG Ultimate+ | DodgysDD），可自动标记流动性扫荡和反转缺口。

二、 核心架构决策：工具取舍与市场状态（Regime）设计


1. 为什么不建议直接套用 AlphaGPT / Qlib 挖掘主信号？

• 架构错配： AlphaGPT（符号回归生成公式因子）和 Qlib（截面多因子排序框架）的设计初衷是针对股票池横截面选股（Cross-Sectional Ranking），计算的是 IC/RankIC，而非单一期货合约的离散事件驱动状态机（Discrete Event State Machine）。
• 正确定位： 必须严格忠实于 DodgysDD 的确定性逻辑作为“信号触发器”，只借用 Qlib 的滚动训练（Rolling Retraining）与概念漂移适应（DDG-DA）思想，或用 AlphaGPT 在离散事件发生的时间点上挖掘“微观辅助特征”（如突破瞬间的量价斜率因子），绝不能用黑盒公式替代 iFVG 规则。

2. 纳斯达克恐慌指数（VXN）与市场 Regime 应变

• 强相关性验证： CBOE VXN 是专门追踪纳斯达克 100 期权隐含波动率的指数（比 VIX 更贴合 NQ，通常比 VIX 高 2–5 点）。
• Regime 划分与参数自适应： 实证研究表明，NQ 的日内波动幅度与均值回归/突破效率在 VXN 不同区间呈现显著非线性特征：
	• 低波震荡期（VXN < 18）： 日均波幅窄（约 200–300 点），假突破多。系统自动收紧过滤条件（仅接受 A+ 级带 SMT 背离信号），止盈目标（RR）下调至 1:1.5 ~ 1:2。
	• 常态趋势期（18 ≤ VXN ≤ 28）： 最适合 DodgysDD 标准模型的黄金区间，结构清晰，止盈目标设在 1:2.5 ~ 1:3 对侧流动性池。
	• 高波恐慌期（VXN > 28）： 流动性极度匮乏，单根 1 分钟 K 线即可扫穿 50 点止损。系统通过 RL 代理自动将单笔风险敞口减半（如从 1% 降至 0.5%），并要求更大的 ATR 最小缺口阈值以过滤插针噪音。

三、 忠实还原 DodgysDD 原始逻辑的状态机（Rule Engine）

在 NautilusTrader 中构建一个名为 DodgysDDStateMachine 的纯规则引擎，严格按照以下 5 步状态流转（完全杜绝事后擦除失效信号）：
1. 大周期背景与时间窗口（HTF & Killzones）：
	• 仅在美东时间 09:30–11:30（NY AM Session） 及 13:30–15:30（NY PM Session） 激活。
	• 标记前日高低点（PDH/PDL）、亚洲/伦敦盘高低点、以及 15m/1H 级别的未回补 FVG。
2. 前置条件 A —— 流动性扫荡（Liquidity Sweep）与 SMT 背离：
	• NQ 刺穿前期波段高点/低点（EQH/EQL/PDH/PDL）。
	• 交叉验证： 同步检查 ES（或 YM）在同一波段是否未能创出新高/新低。若出现 SMT 背离，信号基础权重 +2 分。
3. 前置条件 B —— 反向初始 FVG 识别（Singular FVG）：
	• 扫荡发生前的最后一段推进波中，识别 3 根 K 线构成的常规 FVG（Candle[i-2].high < Candle[i].low 为看涨 FVG，反之亦然），且缺口大小必须大于 0.25 * ATR(14)。
4. 核心触发 —— 反转确认（Inversion Confirmation）：
	• 价格反向运行，在 7 至 15 根 K 线内，出现一根实体收盘价（Body Close）彻底穿透该 FVG 远端边界的 K 线（仅仅影线刺穿不算反转）。
5. 结构净化与目标确认（Checklist 评分）：
	• 无阻挡检查： 确认入场方向前方没有未清理的反向订单块（OB）或紧贴的等高/等低点阻挡。
	• 明确流动性目标（Draw on Liquidity）： 距离入场位至少 2R 处存在明确的 EQH/EQL、未触及的时段高低点或单边流动性（LRLR）。

模块 1：视觉检测模型与规则库交叉验证（Visual-Rule Cross-Validation）

• 解决痛点： 纯数学公式容易把“震荡锯齿中的微小缺口”误判为有效 FVG，而人类交易员一眼就能看出哪些结构干净（Clean Price Action）。
• 实现方案：
	• 在历史数据中，每当规则引擎触发候选 iFVG 时，自动截取过去 60 根 K 线的无指标裸 K 图（使用 mplfinance 后台静默渲染为 224×224 张量）。
	• 微调开源模型（如 Hugging Face 上的 nq-fvg-detector 架构）输出视觉形态置信度（Visual Clarity Score）与边界框重合度（IoU）。
	• 交叉验证规则： 只有当 规则引擎触发 == True 且 视觉模型 IoU > 0.75 时，才放行进入下一层。这能过滤掉约 35% 的假突破噪音。

模块 2：ML 滚动训练（Meta-Labeling 架构）

• 为什么用 Meta-Labeling（元标签）： 传统 ML 直接预测涨跌极易过拟合；Meta-Labeling（由 Marcos López de Prado 提出）让 DodgysDD 规则决定“买卖方向”，让 LightGBM / CatBoost 模型只学习“这次信号能不能赚钱（二分类：1=达到2R止盈，0=触发止损）”。
• 滚动训练（Walk-Forward Rolling）：
	• 训练集窗口：过去 6 个月的候选 iFVG 样本；验证集：最近 1 个月；实盘/测试集：未来 1 个月，每月向前滚动重训。
	• 核心特征集： 规则 Checklist 得分、SMT 是否发生、视觉检测置信度、当前 VXN 绝对值及 1 小时变化率、缺口形成到反转消耗的 K 线数量（越快越强）、距离美股开盘的分钟数。

模块 3：强化学习（RL）动态交易管理

• 作用定位： 严格禁止 RL 自行开仓，仅负责开仓后的仓位管理与离场优化。
• 状态空间（State）： 当前浮动盈亏（以 R 为单位）、VXN 波动率状态、当前持仓时间、订单簿买卖盘失衡度（Order Book Imbalance）。
• 奖励函数（Reward）： 采用下行风险调整收益（Sortino-like Reward），对“达到 1.5R 后不移动止损导致最终亏损”给予额外惩罚，从而训练 RL 学会在合适的波动率下自动触发 Break-Even（保本止损） 和部分止盈。

3. Parquet 格式转换脚本 (data_pipeline/prepare_parquet.py)

python
import pandas as pd
import databento as db
import yfinance as yf
from nautilus_trader.model.identifiers import InstrumentId
from nautilus_trader.model.data import Bar, BarType, BarSpecification
from nautilus_trader.model.enums import BarAggregation, PriceType
from nautilus_trader.model.objects import Price, Quantity
from nautilus_trader.persistence.catalog import ParquetDataCatalog
from nautilus_trader.test_kit.providers import TestInstrumentProvider

def build_nautilus_catalog(nq_dbn_path: str, es_dbn_path: str, catalog_path: str):
    catalog = ParquetDataCatalog(catalog_path)
    
    # 1. 注册标准化期货合约定义 (此处以标准CME规格为例)
    nq_id = InstrumentId.from_str("NQ.XCME")
    es_id = InstrumentId.from_str("ES.XCME")
    
    # 2. 转换 Databento DBN 为 Nautilus Bar 对象
    def ingest_dbn_to_bars(dbn_path: str, inst_id: InstrumentId):
        store = db.DBNStore.from_file(dbn_path)
        df = store.to_df()
        # 过滤展期噪声，保留主力合约成交量最大记录
        df = df.sort_values("volume", ascending=False).groupby(level=0).first().sort_index()
        
        bar_spec = BarSpecification(1, BarAggregation.MINUTE, PriceType.LAST)
        bar_type = BarType(inst_id, bar_spec)
        
        bars = []
        for ts, row in df.iterrows():
            ts_ns = int(ts.value)
            bar = Bar(
                bar_type=bar_type,
                open=Price.from_str(f"{row['open']:.2f}"),
                high=Price.from_str(f"{row['high']:.2f}"),
                low=Price.from_str(f"{row['low']:.2f}"),
                close=Price.from_str(f"{row['close']:.2f}"),
                volume=Quantity.from_int(int(row['volume'])),
                ts_event=ts_ns,
                ts_init=ts_ns,
            )
            bars.append(bar)
        catalog.write_data(bars)
        print(f"成功写入 {len(bars)} 条 {inst_id} 1分钟K线至 Catalog")

    ingest_dbn_to_bars(nq_dbn_path, nq_id)
    ingest_dbn_to_bars(es_dbn_path, es_id)

    # 3. 准备 VXN 指数对齐表 (保存为独立的清洗后 Parquet 供自定义数据流读取)
    vxn_df = yf.download("^VXN", start="2022-01-01", interval="1d")
    # 关键：使用前一日收盘 VXN 作为当日交易的已知状态，防止未来函数
    vxn_df["vxn_known"] = vxn_df["Close"].shift(1).bfill()
    vxn_df["vxn_regime"] = pd.cut(
        vxn_df["vxn_known"], 
        bins=[0, 18.0, 28.0, 200.0], 
        labels=[0, 1, 2] # 0:低波震荡, 1:常态趋势, 2:高波恐慌
    ).astype(int)
    vxn_df[["vxn_known", "vxn_regime"]].to_parquet(f"{catalog_path}/vxn_aligned.parquet")
    print("VXN Regime 数据准备完毕。")

二、 视觉检测模型与规则库交叉验证 (vision_validator/visual_cv.py)

该模块负责在规则引擎检测到候选 iFVG 瞬间，自动将最近 60 根无指标裸 K 线渲染为标准图像，调用目标检测模型（如基于 YOLOv8/v26 微调的 nq-fvg-detector）提取检测框，并计算与规则引擎所识别 FVG 价格区间在像素坐标系下的 IoU（交并比）。

二、核心模块实现概述

接下来的代码模块涵盖了从视觉交叉验证、NautilusTrader 核心状态机到 Meta-Labeling 滚动训练的完整逻辑：
• 视觉与规则交叉验证 (vision_validator/visual_cv.py)：通过 mplfinance 将最近 60 根无指标 K 线渲染为纯黑背景蜡烛图，并利用 YOLOv8 模型预测 FVG 边界框，计算其与规则引擎在垂直价格轴上的 IoU 交并比以过滤噪声信号。
• 自定义数据流与状态机 (strategy/custom_data.py & strategy/state_machine.py)：实现了 VXNRegimeData 自定义事件流，以及 DodgysDDStateMachine 状态机。该状态机严格还原了流动性扫荡（Liquidity Sweep）、跨市场 SMT 背离检测、0.25 ATR 间距判定以及 7–15 根 K 线内的实体反转逻辑。
• 多合约交易策略 (strategy/dodgys_strategy.py)：继承 NautilusTrader Strategy 基类，整合了 NY Killzone 时间窗口过滤、VXN 波动率动态仓位与盈亏比调整、双重交叉验证（视觉 IoU + Meta-Labeling 胜率预测）以及 Bracket 订单执行。
• Meta-Labeling 滚动训练管道 (ml_pipeline/meta_labeling_train.py)：将策略候选日志与回测平仓报告按时间最近邻对齐，生成二分类元标签，并采用带时间隔离带（Embargo）的 Purged Walk-Forward 窗口切分 LightGBM 模型，防止时间序列过拟合。
